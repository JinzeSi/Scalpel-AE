# Confirm Performance Reports

`confirm_perf_reports.py` processes `<commit>-<case>.md` reports in `ROOT/report`.
It uses the existing `generate_perf_report.py` command lookup helpers.

- A report is retained directly only when `redis-<commit>/<case>/symbolic_testcase.txt`
  is nonempty **and the symbolic-mode slowdown meets the threshold** (default 2%).
  Timings and slowdown ratios are validated against the original `final-res.txt`.
- If symbolic values are nonempty but symbolic-mode slowdown is below the threshold,
  a qualifying default-mode slowdown requires a benchmark on clean builds.
- With empty, whitespace-only, or missing symbolic values, a qualifying slowdown
  in either mode requires a benchmark. Cases with neither mode meeting the threshold
  are marked `below_threshold` and excluded; invalid/missing timings require manual review.
- For each benchmark, the old version is the commit's first parent. The new version
  is the reported commit. Both are built from clean local copies of `ROOT/redis`.
- Copies use `git clone --no-hardlinks --no-checkout` and detached checkout. This
  does not modify the source repository or reuse instrumented case binaries.
- Each version runs **one round of 1,000,000 requests with pipeline depth 10**
  (`redis-benchmark -n 1000000 -P 10`), with 50 clients as in redis-benchmark's default.
  The script keeps `--csv` for machine-readable results; it does not change the workload.
  There are no extra benchmark repetitions or warmup requests.
- Builds use the same compiler and `OPTIMIZATION=-O3`. A version is built once per run.
- Both versions use the new version's benchmark client, the same command, and
  separate copies of the same initial RDB. The default data source is recovered
  from the saved `get_redis_2.txt` server command.
- A dedicated port (16379) and private data directories are used. Only the processes
  started by this script are stopped. The original RDB and result directories are preserved.

## Usage

By default, only a read-only plan is printed. No compilation or Redis process runs:

```bash
cd /data3/sjz/AE/redis
python3 confirm_perf_reports.py
```

Run all reports when ready:

```bash
python3 confirm_perf_reports.py --execute
```

Use another project or select reports (repeat `--case` for multiple selections):

```bash
python3 confirm_perf_reports.py --root /path/to/project --source-repo /path/to/clean/redis --execute
python3 confirm_perf_reports.py --case COMMIT-CASE --execute
```

The script also accepts `--report-dir`, `--output-dir`, `--final-dir`, `--data-file`, `--empty-db`,
`--requests`, `--clients`, `--pipeline`, `--jobs`, `--cc`, `--server-cpu`, `--client-cpu`, `--port`,
`--timeout`, `--startup-timeout`, and `--threshold-percent` (default 2).
The output directory must not exist. CPUs default to 45 for the server and 57 for
the client; choose available CPUs on other hosts. The port must be free.
Missing RDB files are not silently replaced by an empty database: supply an RDB or
explicitly choose `--empty-db`.

## Results

After processing the reports, the script automatically writes the final selection
to `ROOT/report-final/<commit>/<commit>-<case>.md` (override the root with
`--final-dir`). Each full commit hash has its own directory containing all retained
cases for that commit, including commits with just one report. This includes
qualifying symbolic reports and reports meeting the benchmark threshold.
No manual copying is needed.
Final reports omit the `modified part` and `icount diff` diagnostics from the
`Original Result` block. Original result files, input reports, and run archives
retain the complete data.

Repeated full runs refresh the script's final reports and remove those no longer
selected, including reports that were not reproduced or could not be verified.
With `--case`, only the selected reports are refreshed; other final reports remain.
Generated reports in the old flat layout are also recognized: refreshed accepted
reports move into commit directories, and obsolete generated copies are removed.
With `--case`, unselected legacy reports remain in their existing locations.
Commit directories are removed only when deleting obsolete reports leaves them empty.
Unrelated files are preserved, and conflicting files not generated by this script
are never overwritten. Dry runs do not change `report-final`. An interrupted run
keeps the previous final selection; its partial results remain in the run archive.

Each execution creates `ROOT/report-confirmation/<timestamp>/`:

- `summary.csv` and `summary.json`: one status per processed report.
- `reports/`: an archived copy of the reports retained during this run.
- `cases/<commit>-<case>/`: original report, symbolic values, version hashes,
  separate old/new server logs, benchmark CSV/stderr, command arguments, and result JSON.
- `builds/<commit>/`: clean source copy, checkout log, and build log.
- `snapshots/`: initial RDB snapshots and their SHA-256 checksums.
- `plan.json` and `settings.json`: inputs and settings for this execution.

The plan and result JSON also record the original symbolic-mode and default-mode
slowdown percentages, so the reason for choosing direct retention or benchmark can
be checked independently of the benchmark measurements.

For equal request counts, elapsed-time slowdown is
`(old_requests_per_second / new_requests_per_second - 1) * 100`.
The benchmark confirms the report when this value is at least the configured
threshold. `not_reproduced` cases remain in the summary but not in `reports/`.
This is a single-round comparison of whole-command throughput, which is a different
measurement from the instrumented timings in the original report.
Request count, client count, and pipeline depth are saved in the settings, measurement
JSON, and confirmation text. Results from runs with different settings are not combined.

Commands requiring interactive client behavior, blocking, transactions, cluster
administration, or nonrepeatable lifecycle operations are marked `manual_review`.
There is no silent fallback to redis-cli and errors are never counted as confirmations.
Compile errors, startup errors, timeouts, and invalid benchmark output are recorded
as `error`; execution continues with other reports. Original reports are never rewritten.

Run the focused tests without launching Redis:

```bash
python3 -m unittest test_confirm_perf_reports.py
```
